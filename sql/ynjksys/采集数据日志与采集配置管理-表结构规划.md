# 采集数据日志与采集配置管理——表结构规划

> **现行策略（2026-08-11）**：客户端凭证不是本模块启用前提。`FAUTHKEYID/FAUTHSECRETENC` 等既有字段、`ClientCredentialTool`、客户端签名及 Java 验签实现保留，但调用代码以注释方式停用；配置文件不要求填写 `auth_key_id/client_secret`。服务端当前只校验 `CLIENT_ID` 已登记、已启用，并核对 `INSTNO/FHIINO` 映射。本文后续若有“凭证必须配置”的旧说明，以本条为准。

> 文档状态：开发基线（规划稿）  
> 更新时间：2026-08-10  
> 数据库：Oracle，业务 Schema 为 `HTLIS`  
> 适用页面：采集数据日志、采集配置管理  
> 注意：本文用于固定设计和指导后续 DDL/接口开发，不是可直接执行的建表脚本。正式执行前必须在 PL/SQL 中核对现有表、字段、约束、索引和存量数据。

## 1. 规划边界

本阶段只升级 HTTP 采集策略，覆盖：

- 客户端注册和当前运行状态；
- 客户端心跳历史；
- 文件发现、上传成功、上传失败等采集业务日志；
- HTTP 采集策略的查看、修改、发布、启用、停用和下载；
- 客户端拉取策略及应用结果回执；
- 平台人工维护日志和客户端自动应用日志；
- “我的采集策略”。

本阶段不开放：

- USB、串口策略的远程编辑；
- 脚本存储、在线调试和远程执行；
- 项目对照表、原始记录数据源与客户端配置文件的混合下发。

项目对照表和数据源管理仍可保留在“采集配置管理”页面中，但作为独立业务页签和独立数据表开发，不进入本次客户端 HTTP 策略链路。

## 2. 操作主体和平台固定字段

### 2.1 平台人工操作

平台页面从父窗口取得当前用户信息：

```javascript
var s = window.parent.reEcdtJ.sInfo;

var userName = s.empNm;              // 用户姓名，如“监*一”
var empId = s.empId || s.opNo;       // 当前系统中 opNo 与 empId 相同，如 S11
var hiiNo = s.hiiNo;                 // 当前机构，如 5300003
```

人工新增、修改、发布、启用、停用策略时，固定字段写入规则：

| 字段 | 写入值 | 示例 |
|---|---|---|
| `FEMPID` | 当前平台操作人 `empId/opNo` | `S11` |
| `FOPDT` | 数据库或服务端时间 | `SYSDATE` |
| `FHIINO` | 当前平台机构 `hiiNo` | `5300003` |

注册 SQL 使用：

```text
empid_sql_equal
empnm_sql_equal（页面或日志确需姓名时）
hiino_sql_equal
```

`USER NAME` 不是本模块统一固定字段。页面显示姓名时：

1. 当前操作页面优先使用 `reEcdtJ.sInfo.empNm`；
2. 历史列表根据 `FEMPID` 关联平台操作员/人员表取得姓名；
3. 若后续审计要求保存不可变姓名，再在审计表增加姓名快照字段，不修改固定字段语义。

### 2.2 客户端自动操作

心跳、采集日志、策略拉取和策略应用回执不是人工操作，不写入 `S11`：

| 字段 | 写入规则 |
|---|---|
| `FEMPID` | 已注册的 `CLIENT_ID`，如 `AGILENT-1200` |
| `FOPDT` | Java 服务端实际接收/入库时间 |
| `FHIINO` | Java 根据 `CLIENT_ID` 从客户端注册表取得，禁止直接信任 HTTP 报文中的机构值 |

策略日志通过 `FOPERATORTYPE` 区分：

```text
USER    平台人工操作
CLIENT  客户端自动操作
SYSTEM  服务端自动任务
```

## 3. 总体表关系

```text
HTLIS.LIS_CLIENT_INFO
    ├── HTLIS.LIS_HEARTBEAT_LOG
    ├── HTLIS.LIS_ACQUISITION_LOG
    └── HTLIS.LIS_CLIENT_POLICY
            └── HTLIS.LIS_CLIENT_POLICY_LOG
```

| 表 | 当前状态 | 作用 |
|---|---|---|
| `LIS_CLIENT_INFO` | 已有，增量升级 | 客户端注册信息和最新状态 |
| `LIS_HEARTBEAT_LOG` | 已有，增量升级 | 每次心跳的历史快照 |
| `LIS_ACQUISITION_LOG` | 已有预留表，增量升级并启用 | 文件发现、上传和配置应用等业务日志 |
| `LIS_CLIENT_POLICY` | 计划新建 | 每个客户端当前策略及发布版本 |
| `LIS_CLIENT_POLICY_LOG` | 计划新建 | 策略变更、发布、拉取和应用审计日志 |

## 4. HTLIS.LIS_CLIENT_INFO

### 4.1 业务定位

- 一台已注册客户端一条记录；
- `CLIENT_ID` 为稳定唯一标识；
- 保存注册归属、软件版本和最新运行状态；
- 客户端未知或未启用时，Java 接口拒绝心跳和策略拉取；
- `LAB_ID` 仅作为实验室显示/业务编码，权限和数据隔离以 `FHIINO` 为准。

### 4.2 现有字段保留

| 字段 | 类型 | 说明 |
|---|---|---|
| `CLIENT_ID` | `VARCHAR2(100)` | 主键，客户端唯一编号 |
| `CLIENT_TYPE` | `VARCHAR2(20)` | `python`、`go` |
| `CLIENT_VER` | `VARCHAR2(40)` | 客户端程序版本 |
| `LAB_ID` | `VARCHAR2(50)` | 实验室业务编码，仅供显示/分组 |
| `INSTNO` | `VARCHAR2(100)` | 仪器/解析接口编号 |
| `OS_INFO` | `VARCHAR2(200)` | 操作系统信息 |
| `INSTALL_TIME` | `DATE` | 首次登记/首次上线时间 |
| `LAST_HEARTBEAT` | `DATE` | 最近心跳时间 |
| `CURRENT_STATUS` | `VARCHAR2(20)` | 当前状态 |
| `RUNNING_MODE` | `VARCHAR2(30)` | 当前运行模式，本阶段为 `http` |
| `UPLOAD_TOTAL` | `NUMBER` | 客户端累计上传成功数 |
| `UPLOAD_FAIL` | `NUMBER` | 客户端累计上传失败数 |
| `UPTIME_SEC` | `NUMBER` | 本次启动累计运行秒数 |

### 4.3 计划增加字段

| 字段 | 建议类型 | 必填 | 说明 |
|---|---|---:|---|
| `FGUID` | `VARCHAR2(60)` | 是 | 平台业务全局唯一标识；`CLIENT_ID`仍作为客户端业务主键 |
| `FEMPID` | `VARCHAR2(60)` | 是 | 最后自动更新主体，心跳更新时为已认证的 `CLIENT_ID` |
| `FOPDT` | `DATE DEFAULT SYSDATE` | 是 | 最后更新时间 |
| `FHIINO` | `NUMBER(12)` | 是 | 服务端确认的数据所属机构 |
| `FREGEMPID` | `VARCHAR2(60)` | 是 | 在平台登记该客户端的人员编号 |
| `FREGDT` | `DATE` | 是 | 平台登记时间 |
| `FENABLE` | `VARCHAR2(10)` | 是 | `是/否`，是否允许客户端访问接口 |
| `FAPPLIEDVER` | `VARCHAR2(40)` | 否 | 客户端已应用的策略版本 |
| `FAPPLYSTATUS` | `VARCHAR2(20)` | 否 | `NONE/PENDING/SUCCESS/FAILED` |
| `FAPPLYMSG` | `VARCHAR2(2000)` | 否 | 最近一次策略应用结果 |
| `FLASTCONFIGDT` | `DATE` | 否 | 最近策略拉取或应用时间 |
| `FAUTHKEYID` | `VARCHAR2(60)` | 否 | 客户端凭证标识，不是密钥本身 |
| `FAUTHSECRETENC` | `VARCHAR2(1000)` | 否 | 服务端加密保存的客户端密钥，不允许页面回显 |
| `FAUTHSTATUS` | `VARCHAR2(20)` | 否 | `ACTIVE/DISABLED/EXPIRED` |
| `FDPTNO` | `VARCHAR2(60)` | 否 | 客户端/仪器所属部门，用于页面实验室筛选；优先取已登记设备或接口定义，不信任客户端报文 |

### 4.4 约束与索引规划

```text
PK  (CLIENT_ID)
UK  (FGUID)
IDX (FHIINO, FENABLE)
IDX (FHIINO, INSTNO)
IDX (FHIINO, LAST_HEARTBEAT)
IDX (CURRENT_STATUS, LAST_HEARTBEAT)
```

### 4.5 写入规则

- 客户端必须先由平台登记，未知 `CLIENT_ID` 不再由首个心跳自动注册；
- 登记时：`FREGEMPID=S11`、`FHIINO=5300003`；
- 心跳时：`FEMPID=CLIENT_ID`、`FOPDT=服务端时间`；
- 心跳报文中的 `INSTNO/LAB_ID` 只能用于核对，不得覆盖服务端注册归属；
- 当前在线状态由 `LAST_HEARTBEAT` 与服务端阈值计算，不只信任 `CURRENT_STATUS`。

## 7. HTLIS.LIS_CLIENT_POLICY（计划新建）

### 7.1 业务定位

- 保存客户端当前策略；
- 一个客户端最多一条当前策略；
- 草稿保存不会影响客户端；
- 发布后生成新的 `CONFIG_VER`，客户端才可拉取；
- “我的采集策略”按 `FOWNEREMPID` 查询，不能按最后修改人查询。

### 7.2 字段规划

| `FGUID` | `VARCHAR2(60)` | 是 | 主键 |

| `FDPTNO` | `VARCHAR2(60)` | 否 | 所属部门快照，用于页面筛选 |
| `FOWNEREMPID` | `VARCHAR2(60)` | 是 | 策略创建人/归属人 |
| `CONFIG_VER` | `VARCHAR2(40)` | 是 | 如 `v2_20260810153000` |
| `POLICY_STATUS` | `VARCHAR2(20)` | 是 | `DRAFT/PUBLISHED/DISABLED` |

| `FILE_PATH` | `VARCHAR2(1000)` | 是 | 客户端监听目录 |
| `SCAN_INTERVAL` | `NUMBER(10)` | 是 | 扫描间隔秒数 |
| `SERVICE_URL` | `VARCHAR2(500)` | 是 | 服务地址，发布时校验白名单 |
| `START_ROW` | `NUMBER(10)` | 否 | 解析起始行 |
| `SAMP_COL_FLAG` | `VARCHAR2(100)` | 否 | 样品列标记 |
| `TRACK_MODE` | `NUMBER(2)` | 是 | 去重跟踪模式 |

| `FILE_NAME_TEMPLATE` | `VARCHAR2(500)` | 否 | 文件命名规则 |
| `FPUBLISHEDDT` | `DATE` | 否 | 最近发布时间 |
| `FEMPID` | `VARCHAR2(60)` | 是 | 最后平台操作人，由平台注册 SQL 从已校验会话取得 |
| `FOPDT` | `DATE DEFAULT SYSDATE` | 是 | 最后操作时间 |
| `FHIINO` | `NUMBER(12)` | 是 | 当前机构 |

### 7.3 约束与索引规划

```text
PK  (FGUID)
UK  (CLIENT_ID)
IDX (FHIINO, POLICY_STATUS)
IDX (FHIINO, FOWNEREMPID)
IDX (FHIINO, FOPDT)
```

### 7.4 版本规则

```text
v1_yyyyMMddHHmmss
v2_yyyyMMddHHmmss
```

- 修改草稿不改变已发布版本；
- 每次发布版本号递增并带发布时间戳；
- 客户端比较 `CONFIG_VER` 与 `FAPPLIEDVER` 判断是否需要更新。
- `POLICY_NAME` 是平台展示和审计元数据；仅修改名称不生成新 `CONFIG_VER`，也不触发客户端重新应用配置。

## 9. HTTP 接口与表写入关系

### 9.1 UploadClientLog.m

```text
心跳
  → UPDATE LIS_CLIENT_INFO
  → INSERT LIS_HEARTBEAT_LOG

采集业务日志
  → INSERT LIS_ACQUISITION_LOG
```

服务端必须先按 `CLIENT_ID` 查询 `LIS_CLIENT_INFO`，取得可信 `INSTNO/FHIINO/FENABLE`，再写日志。

### 9.2 GetClientConfig.m（计划新增）

```text
客户端提交 CLIENT_ID + 当前版本 + 凭证
  → 校验 LIS_CLIENT_INFO
  → 查询 LIS_CLIENT_POLICY.POLICY_STATUS='PUBLISHED'
  → 有新版本时返回 HTTP 策略
  → 写 LIS_CLIENT_POLICY_LOG(CLIENT_PULL)
```

### 9.3 UploadClientConfigAck.m（计划新增）

```text
客户端提交 CONFIG_VER + 应用结果
  → 更新 LIS_CLIENT_INFO.FAPPLIEDVER/FAPPLYSTATUS/FAPPLYMSG
  → 写 LIS_CLIENT_POLICY_LOG(APPLY_SUCCESS/APPLY_FAIL)
  → 必要时同步写 LIS_ACQUISITION_LOG
```

### 14.3 UploadClientLog 当前已实现能力

当前 `UploadClientLog.java` 已实现：

1. 通过 `dataquote` 接收 URL 编码 JSON；
2. 读取 `client_id/client_type/client_ver/lab_id/instno/heartbeat_seq/status/mode/upload_total/upload_fail/uptime_sec/os`；
3. 按 `CLIENT_ID` 查询 `LIS_CLIENT_INFO`；
4. 已存在时更新客户端当前状态，不存在时自动插入；
5. 每次请求向 `LIS_HEARTBEAT_LOG` 插入一条心跳；
6. 两步写入使用同一数据库事务，成功提交，异常回滚；
7. Python 与 Go 客户端当前都能按该字段集合构造 `UploadClientLog.m` 请求。

因此，在旧版三表结构完全匹配、客户端提供非空 `CLIENT_ID` 的情况下，该类具备基础心跳 UPSERT/INSERT 能力。

2026-08-10 已使用工程现有 JDK 8 和 SVN 依赖对该单类执行非侵入式 `javac` 编译，成功生成 `UploadClientLog.class`。该结果证明当前源码在工程依赖下可以编译；尚未执行 Oracle 集成测试，不能把“编译通过”等同于“数据库链路和业务要求已验证通过”。

### 14.4 UploadClientLog 代码缺口

当前实现与本规划的实际业务要求仍有以下偏差：

1. `initProperties()` 使用虚拟 `sessionId` 绕过平台会话，但没有建立替代的客户端身份认证；
2. 未校验客户端凭证、时间戳、随机数和签名，知道接口地址与 `CLIENT_ID` 即可伪造心跳；
3. 未知 `CLIENT_ID` 会自动注册，不符合“平台预登记客户端后才允许接入”的边界；
4. `LAB_ID`、`INSTNO` 直接信任客户端报文，客户端可以覆盖注册信息；
5. 未从注册表解析可信 `FHIINO`，也未写入 `FEMPID/FOPDT/FHIINO/FGUID`；
6. 仅检查 `CLIENT_ID` 非空，未校验字段长度、状态词典、运行模式、计数非负和版本格式；
7. 使用“先查询、后插入”的注册方式，并发首次心跳存在主键竞争风险；
8. `HEARTBEAT_SEQ` 没有唯一约束或幂等判断，重试会生成重复心跳；
9. 未写 `LIS_ACQUISITION_LOG`，无法形成文件发现、上传成功、上传失败等客户端消息日志；
10. 成功响应只给出 `result=success`，未返回服务端时间、当前策略版本或是否需要拉取配置；
11. 通用异常分支未形成稳定的业务错误码和可对接错误消息；
12. 该文件只在 SVN 路径发现，CodeTalkers 开发工作区没有同版本文件，存在开发源与正式源不一致风险。

### 14.5 UploadClientLog 目标改造边界

该接口后续保留“心跳”单一职责，目标处理顺序固定为：

```text
读取请求
  → 校验 CLIENT_ID、时间戳、随机数、HMAC 签名
  → 从 LIS_CLIENT_INFO 取得可信 INSTNO/FHIINO/FENABLE/FAUTHSTATUS
  → 校验客户端上报 INSTNO 与登记值一致
  → MERGE 更新客户端当前状态
  → 幂等插入心跳快照
  → 返回服务端时间、已发布策略版本、是否需要拉取
```

服务端写入规则：

```text
FEMPID = 已认证 CLIENT_ID
FOPDT  = 服务端 SYSDATE/当前时间
FHIINO = LIS_CLIENT_INFO.FHIINO
```

客户端报文中的 `LAB_ID/INSTNO` 只用于一致性检查，不能作为数据库归属和授权依据。

### 14.6 UploadClientEvent 计划接口

为了让“客户端消息日志”展示真实日志，需要新增独立事件接口，不把大量业务事件混入心跳表。

建议请求字段：

```text
client_id, client_ver, event_id, event_time,
log_level, log_type, instno,
file_name, file_size, fdiseq,
result_status, http_status, duration_ms,
retry_count, error_code, message, raw_detail
```

处理要求：

- 复用与心跳接口相同的客户端鉴权；
- 按 `EVENT_ID` 或 `CLIENT_ID + EVENT_ID` 保证重试幂等；
- `FHIINO/INSTNO` 以注册信息为准；
- 成功写入 `LIS_ACQUISITION_LOG` 后返回明确业务结果；
- `RAW_DETAIL` 限长、脱敏，不允许客户端上传数据库密码、凭证明文或任意超大日志文件；
- 文件上传成功事件可回填 `FDISEQ`，用于与归档文件和解析结果联查。

### 14.7 GetClientConfig 计划接口

建议请求字段或请求头：

```text
client_id, client_ver, current_policy_ver, timestamp, nonce, signature
```

接口必须：

1. 校验客户端身份和启用状态；
2. 只返回该客户端当前 `PUBLISHED` 且有效的 HTTP 策略；
3. 客户端版本已是最新时返回 `changed=false`，不重复下发完整配置；
4. 返回 `policy_ver/policy_hash/published_time/config`；
5. 配置只包含允许远程维护的白名单字段；
6. 写入 `LIS_CLIENT_POLICY_LOG` 的 `CLIENT_PULL` 记录；
7. 不返回凭证明文，不允许跨 `CLIENT_ID/FHIINO` 获取策略。

首阶段 HTTP 配置白名单建议为：

```text
filepath, frequency, service, allowed_extensions,
track_mode, heartbeat_interval, request_timeout,
retry_count, retry_interval
```

`client_id/instno/client_type/client_ver/auth_secret` 不允许通过普通策略远程覆盖。

### 14.8 UploadClientConfigAck 计划接口

建议请求字段：

```text
client_id, client_ver, policy_ver, policy_hash,
apply_status, apply_time, error_code, apply_message,
timestamp, nonce, signature
```

接口必须：

- 校验客户端身份、策略版本和策略摘要；
- 只允许 `SUCCESS/FAIL` 两种应用结果；
- 更新 `LIS_CLIENT_INFO.FAPPLIEDVER/FAPPLYSTATUS/FAPPLYMSG/FLASTCONFIGDT`；
- 写入 `LIS_CLIENT_POLICY_LOG` 的 `APPLY_SUCCESS/APPLY_FAIL`；
- 失败回执保留原因，但不能把客户端本地敏感配置写入日志；
- 重复回执必须幂等。

### 16.2 统一请求鉴权

四个接口均使用`multipart/form-data`：

```text
dataquote       = URL编码后的JSON原文
auth_key_id     = LIS_CLIENT_INFO.FAUTHKEYID
auth_timestamp  = Unix秒级时间戳，服务端允许正负300秒
auth_nonce      = 8~100位随机字符串
auth_signature  = HMAC-SHA256十六进制小写
```

签名原文固定为：

```text
client_id + "\n" + auth_timestamp + "\n" + auth_nonce + "\n" + URL解码后的dataquote JSON原文
```

服务端先按`CLIENT_ID`读取已登记的`INSTNO/FHIINO/FENABLE/FAUTHSTATUS`，再验签。客户端报文中的`INSTNO`只用于一致性核对，不能覆盖服务端登记归属。凭证密文使用`v1:Base64(iv):Base64(ciphertext)`，主密钥由JVM参数`syssjcj.client.masterKey`或环境变量`SYSSJCJ_CLIENT_MASTER_KEY`提供，源码不保存主密钥和客户端明文密钥。

### 16.3 接口契约

#### UploadClientLog.m

`dataquote`至少包含：

```json
{"client_id":"AGILENT-1200","client_ver":"v2_20260810153000","instno":"AGILENT-1200","heartbeat_seq":1,"status":"RUNNING","mode":"http","upload_total":8,"upload_fail":2,"uptime_sec":3600}
```

状态仅允许`RUNNING/STOPPED/ERROR`，响应参数包含`config_version/config_changed`。当前 Python/Go 客户端进程重启后 `HEARTBEAT_SEQ` 会从 1 重新计数，因此 `CLIENT_ID+HEARTBEAT_SEQ` 不能作为跨启动周期唯一键；Java 现有的同键去重逻辑需在引入客户端启动批次 `RUN_ID` 后改为 `CLIENT_ID+RUN_ID+HEARTBEAT_SEQ`，否则会误忽略重启后的心跳。

#### UploadClientEvent.m

`dataquote`至少包含：

```json
{"client_id":"AGILENT-1200","event_id":"32位或60位内唯一标识","event_time":"2026-08-10 15:30:00","log_type":"UPLOAD_SUCCESS","log_level":"INFO","result_status":"SUCCESS","request_guid":"上传请求标识"}
```

事件类型仅允许本文6.4定义值；结果仅允许`SUCCESS/FAILED/INFO`。`FGUID`或同一客户端的`REQUEST_GUID`重复时不重复写入。

#### GetClientConfig.m

请求JSON：

```json
{"client_id":"AGILENT-1200","instno":"AGILENT-1200","current_policy_ver":"v2_20260810153000","current_policy_hash":"sha256"}
```

只返回同一`CLIENT_ID+INSTNO+FHIINO`下状态为`PUBLISHED`的策略；返回`changed/policy_ver/policy_hash/config`。策略内容哈希由服务端按有序JSON动态计算。

#### UploadClientConfigAck.m

请求JSON：

```json
{"client_id":"AGILENT-1200","instno":"AGILENT-1200","policy_ver":"v2_20260810153000","policy_hash":"sha256","apply_status":"SUCCESS","apply_message":"配置已应用"}
```

只接受`SUCCESS/FAILED`，先复算发布策略摘要，再更新客户端应用状态并以`CLIENT_ID+CONFIG_VER+ACTION_TYPE`幂等写回执日志。
